This audit read both pages from the recovered local extraction. The full PDF/extraction is not in the publication allowlist.

Page1 resolves field/status definitions: T denotes continuous trading, L closing auction, and three-character cross-period codes have I or Q first (book-level information or transaction), an instrument-status character second, and a cross-type character third. The third character C denotes closing cross. IOO therefore denotes opening-related book information. Observed QTA has a third character A not covered by this2020revision; it must not be guessed to mean closing auction.

The document explicitly describes use of both cross and non-cross transactions in reconstructed order books. Therefore the absent closing records in the received files cannot be described as a documented universal intentional exclusion. We have found a discrepancy/coverage limitation for specific delivered files, not established its cause.

TIME is described as an event timestamp with nanosecond precision. Neither page states UTC, exchange-local timezone, a DST rule or a fixed offset. Raw ITCH UTC does not by itself establish the transformed CSV clock. Clock/source-phase consistency may be assessed separately and explicitly labelled an inference.

Page2 describes other products: Trade Ticker includes message TYPE and MATCHNUMBER, Order Book View includes raw order references, and Full Day Timeserie provides a JSON message sequence. These could resolve auction/correction metadata if currently accessible, but current availability has not been established. The raw products' PRICE description includes four implied decimals; this MUST NOT be automatically applied to reconstructed ASKPX/BIDPX/TXPX, whose field definitions are different.

Primary-price-only gate remains unchanged. Exact final auction price can come from a separately validated vendor field; participant/match completeness is only needed for any later volume/order-flow question, which is outside this pilot.
